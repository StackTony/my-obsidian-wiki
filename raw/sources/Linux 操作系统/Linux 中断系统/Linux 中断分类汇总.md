## 一、同步中断（异常 Exception）

同步中断由CPU执行指令时主动产生，触发时机与当前指令严格同步，中断向量号由CPU内部定义，无需外部中断控制器参与。按可恢复性与返回行为分为三类：

### 1. 故障（Fault）

- **核心特征**：可恢复类异常，异常发生时CPU保存的指令指针（PC/RIP）**指向触发异常的当前指令**；异常处理完成后，返回并重新执行该指令。
- **常见类型补充说明**：
    - **缺页异常（Page Fault）**：最典型的故障类异常，既包含正常的按需调页、写时复制（COW）等可恢复场景，也包含非法地址访问、权限越界等不可恢复场景（此时内核会向进程发送SIGSEGV信号终止进程）。
    - **一般保护性异常（#GP）**：触发场景涵盖用户态执行特权指令、访问越权内存地址、段权限违规、部分架构下的非对齐内存访问等。
    - 除零异常、非法操作码异常均属于典型故障，处理后可重新执行（通常由内核模拟指令或上报信号）。

### 2. 陷阱（Trap）

- **核心特征**：预期内的主动触发，异常发生在**陷阱指令执行完成之后**，CPU保存的指令指针指向当前指令的下一条；处理完成后直接继续执行后续代码，无需重跑原指令。
- **常见类型补充说明**：
    - **系统调用**：`int 0x80`（32位x86）通过陷阱门触发，是标准陷阱实现；x86_64的`syscall`、ARM的`svc`指令为快速系统调用机制，不走传统中断描述符表，但行为上仍属于同步陷阱。
    - 断点异常（`int3`）、单步调试、溢出检测指令（`into`）均是程序主动插入的调试/检测点，属于典型陷阱。

### 3. 终止（Abort）

- **核心特征**：严重的不可恢复错误，CPU无法准确定位出错指令，保存的PC值无意义；内核通常无法修复，只能终止进程或触发内核崩溃（Kernel Panic/蓝屏）。
- **常见类型补充说明**：
    - **双重故障（#DF）**：典型场景为内核栈溢出，处理第一个异常时又触发新的异常；若双重故障处理过程中再触发异常，会进入三重故障，直接导致CPU硬件复位。
    - **机器检查异常（#MC）**：由硬件上报的物理故障（如缓存ECC错误、总线奇偶错误、内存不可纠正错误）；现代服务器CPU配合ECC内存可实现部分可纠正的MCE处理，并非全部直接崩溃。

## 二、异步中断（硬件中断 Interrupt）

异步中断由外部硬件或核间信号随机触发，与CPU当前执行的指令无同步关系，通过中断控制器（APIC/GIC）进行路由和优先级管理。

### 1. 外部外设硬中断

- **核心特征**：由板载外设或外接设备通过物理引脚触发，经中断控制器分发到CPU核心。
- **架构分类补充**：
    - **ARM GIC 体系**：
        - PPI（私有外设中断）：每个CPU核心专属，如本地定时器中断、性能监控中断，无法路由到其他核。
        - SPI（共享外设中断）：全系统共享的外设中断，如网卡、硬盘、USB控制器中断，可由GIC配置路由到单个或多个CPU核心，是SMP中断亲和性的硬件基础。
    - **触发方式**：分为电平触发（中断线保持电平直到被处理）和边沿触发（电平跳变时触发一次），现代APIC/GIC均支持两种模式。

### 2. 消息信令中断（MSI / MSI-X / LPI）

- **核心特征**：无需物理中断引脚，设备通过向指定内存地址写入特定数据包触发中断，是PCIe等高速总线的标准中断方式。
- **类型差异补充**：
    - **MSI**：基础版消息中断，最多支持32个中断向量，且向量号必须连续。
    - **MSI-X**：增强版，最多支持2048个独立向量，每个向量可单独配置目标地址、数据和路由CPU；是多队列网卡、NVMe SSD的标配，可实现“一个队列对应一个中断、绑定一个CPU核心”的极致并行。
    - **LPI（局域外设中断）**：ARM GICv3/v4 引入的中断类型，配合ITS（中断翻译服务）单元，将PCIe的MSI/MSI-X请求转换为内部LPI，支持超大规模中断向量。

### 3. 处理器间中断（IPI）

- **核心特征**：多核系统中CPU核心之间主动发送的中断，是核间协同的核心机制。
- **架构对应与补充场景**：
    - x86平台通过本地APIC（LAPIC）发送IPI；ARM平台通过SGI（软件生成中断）实现同等功能。
    - 典型场景补充：除TLB刷新、调度抢占、函数广播外，还包括缓存一致性同步、系统停机时的多核停机、时钟事件广播等。

### 4. 不可屏蔽中断（NMI）

- **核心特征**：最高优先级中断，无法通过普通中断屏蔽指令（如x86的`cli`）关闭，保证极端场景下CPU必须响应。
- **两类典型场景**：
    - **硬件故障类**：如硬件看门狗超时、内存不可纠正ECC错误、总线致命错误，通常直接触发系统崩溃。
    - **调试监控类**：如Linux的NMI Watchdog（死锁检测）、perf硬件性能采样，利用NMI不可屏蔽的特性，在关中断场景下也能采集CPU状态，定位死锁与性能问题。

## 三、同步异常 vs 异步中断 核心对比

|对比维度|同步异常（Exception）|异步硬件中断（Interrupt）|
|---|---|---|
|触发时机|与指令执行严格同步，执行当前指令时产生|与当前指令无关，随机异步触发|
|触发源|CPU内部，指令执行异常或主动触发|外部硬件、其他CPU核心|
|PC指向|故障：指向当前指令；陷阱：指向下一条|指向被打断的下一条指令|
|可预期性|大部分可预期（如系统调用、缺页）|完全随机，不可预期|
|中断向量|CPU架构预定义，固定编号|由中断控制器动态分配/配置|
|典型代表|缺页、系统调用、断点|网卡中断、定时器中断、IPI|

## 四、易混淆概念澄清

1. **软中断（Softirq）、Tasklet 不属于异步硬件中断** 二者是Linux内核的**中断下半部机制**，属于软件层面的延迟处理逻辑，用于将中断处理中耗时的部分后移，不占用硬件中断上下文，不要与硬件中断混为一谈。
2. **中断上半部 vs 下半部** 上半部即硬件中断处理函数，快速响应硬件、清中断标志、登记工作；下半部（软中断、tasklet、工作队列）负责后续耗时的数据处理，在开中断环境下执行。
3. **ARM SGI 与 IPI 的关系** SGI是ARM GIC提供的软件生成中断，IPI是核间中断的功能概念；ARM平台的IPI功能就是通过SGI中断实现的，二者是实现与功能的对应关系。
