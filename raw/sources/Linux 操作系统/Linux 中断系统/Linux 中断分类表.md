## 分类总览：先厘清分类维度

中断的分类容易混淆，根源在于存在多个不同视角的维度。本文厘清四个维度：**维度一、二是机制维度**（相互正交、最核心），**维度三是 Linux 内核特有的处理阶段划分**，**维度四是功能/用途视角**（"I/O 中断""定时器中断""网卡 IRQ"等叫法属于此维度）。正文按最本质的**维度一（同步/异步）**组织，通俗叫法在总览中统一对齐。

### 维度一：按触发时机分（CPU 架构视角，最本质）

- **同步中断（异常 Exception）**：由 CPU 执行指令的行为引发——或是软件主动执行软中断指令，或是指令执行中被动出错——触发时机与当前指令严格同步，中断向量号由 CPU 架构预定义，无需外部中断控制器参与。
- **异步中断（硬件中断 Interrupt）**：由外部硬件或核间信号随机触发，与 CPU 当前执行的指令无任何同步关系，经中断控制器（APIC/GIC）路由和优先级管理。

### 维度二：按触发来源分（"硬/软"的通俗叫法）

- **硬中断**：即异步硬件中断（= 维度一中的异步中断），来源是外部硬件或其他 CPU 核心。
- **"软中断"是歧义词**，有三重含义：
    1. **狭义软中断（指令级）**：软件主动执行的中断指令（x86 的 `INT n`、ARM 的 `SVC/SWI`）——本质是**同步陷阱（Trap）**，用于系统调用；
    2. **广义软件中断**：泛指一切由 CPU 内部执行指令或程序运行错误产生的同步中断（= 异常 Exception，涵盖 Fault/Trap/Abort），与外部硬件来源相对；
    3. **Linux 内核语境的 Softirq**：内核的**下半部延迟处理机制**——根本不是硬件意义上的中断。

### 维度三（Linux 内核特有的延伸）：按处理时机分

这是对中断**处理阶段**的划分，不是对中断**类型**的划分：

- **上半部（Top Half）**：硬中断处理函数本身，关中断、快速执行；
- **下半部（Bottom Half）**：Softirq / Tasklet / 工作队列，开中断、延后执行。

### 维度四：按功能/用途分（教科书与内核工程视角）

经典教材（如《Understanding the Linux Kernel》）与 x86 体系文档常按**功能来源**归纳硬件中断：**I/O 中断、定时器中断、处理器间中断（IPI）、本地/错误监控中断**。注意：功能维度与机制维度**正交但不能平行混用**——"网卡中断"（功能标签）与"MSI-X"（机制实现）不在同一层级。二者的映射关系：

| 功能类型 | 典型例子 | 机制归属（对应第 1 章小节） |
|---|---|---|
| **I/O（外设）中断** | 网卡收发包、NVMe I/O 完成、键鼠输入 | 老式设备走引脚中断（SPI / IOAPIC IRQ，§1）；现代高速设备（多队列网卡、NVMe）标配 MSI/MSI-X/LPI（§2） |
| **定时器中断** | 系统 tick/心跳、高精度定时器、调度抢占 | ARM 架构定时器走 PPI（§1）；x86 走本地 APIC 定时器（LVT 本地中断，§5）或 HPET（MSI/引脚）、老式系统走 PIT（IRQ0）；跨核 tick 广播走 IPI（§3） |
| **处理器间中断（IPI）** | 调度负载均衡、TLB Shootdown、多核停机 | IPI（x86 LAPIC）/ SGI（ARM GIC）（§3） |
| **本地/错误监控中断** | APIC 错误、温度传感器、性能计数器溢出（PMU 采样） | x86 LAPIC LVT 本地中断（§5）；ARM 的 PMU/温控多为 PPI（§1） |

（NMI 不列入此表：它按可屏蔽性单独归类（§4），功能上横跨硬件故障上报与调试监控。）

### 分类树

```
中断与异常
├── 同步中断（异常 Exception）—— 由指令执行引发，向量号由 CPU 架构预定义
│   ├── 故障 Fault（缺页、#GP、#DE、#UD）→ 处理后重新执行当前指令
│   ├── 陷阱 Trap（软中断指令 INT n/SVC、INT3 断点、单步调试、INTO）→ 继续执行下一条指令
│   │    └── 软中断指令（INT n / SVC / SWI）＝ 狭义"软中断"，是 Trap 的子类
│   └── 终止 Abort（#DF 双重故障、#MC 机器检查）→ 不可恢复，终止进程 / 内核崩溃
└── 异步中断（硬件 Interrupt，俗称"硬中断"）—— 随机到达，经中断控制器路由
    ├── 外部外设中断（物理引脚）：ARM GIC 的 PPI / SPI；电平触发 / 边沿触发
    ├── 消息信令中断（内存写报文）：MSI / MSI-X（PCIe）、LPI（GICv3 + ITS）
    ├── 处理器间中断 IPI：x86 LAPIC IPI / ARM SGI
    ├── 本地中断（每核私有、核内资源）：x86 LAPIC LVT（定时器/性能计数/温控/错误）；ARM 的 PPI 与之概念对应
    └── 不可屏蔽中断 NMI：无法通过 cli 等指令关闭
```

### 术语 × 维度归属速查

| 术语 | 同步/异步 | 软/硬 | 本质 |
|---|---|---|---|
| 异常（Fault/Trap/Abort） | 同步 | 软件来源（广义"软中断"） | CPU 内部执行错误或主动陷阱 |
| 软中断指令（INT n / SVC） | 同步 | 软件 | 陷阱（Trap）的子类 |
| 硬件中断（PPI/SPI、MSI/LPI、IPI/SGI、LVT 本地中断、NMI） | 异步 | 硬件（"硬中断"） | 外部硬件 / 其他核心 / 核内本地资源发起 |
| Linux Softirq | ——（非硬件中断） | 内核软件机制 | 下半部延迟处理上下文 |

## 一、异步中断（硬件中断，即"硬中断"）

异步中断由外部硬件或核间信号随机触发，与 CPU 当前执行的指令无同步关系，通过中断控制器（APIC/GIC）进行路由和优先级管理，向量号由操作系统经中断控制器分配配置，而非 CPU 架构预定义。

### 1. 外部外设硬中断（物理引脚）

- **核心特征**：由板载外设或外接设备通过==🟡**物理引脚**==触发，经中断控制器分发到 CPU 核心。
- **架构分类（ARM GIC 体系）**：
    - **PPI（私有外设中断）**：每个 CPU 核心专属，如本地定时器中断、性能监控中断，无法路由到其他核，是某个CPU核心所独有的。
    - **SPI（共享外设中断）**：全系统共享的外设中断，如网卡、硬盘、USB 控制器中断，可由 GIC 配置路由到单个或多个 CPU 核心，是 SMP 中断亲和性的硬件基础。
- **触发方式**：分为电平触发（中断线保持电平直到被处理）和边沿触发（电平跳变时触发一次），现代 APIC/GIC 均支持两种模式。

### 2. 消息信令中断（MSI / MSI-X / LPI）

- **核心特征**：无需物理中断引脚，设备通过==🟡**向指定内存地址写入特定数据包**==触发中断，是 PCIe 等高速总线的标准中断方式。
- **类型差异**：
    - **MSI**：基础版消息中断，最多支持 32 个中断向量，且向量号必须连续。
    - **MSI-X**：增强版，最多支持 2048 个独立向量，每个向量可单独配置目标地址、数据和路由 CPU；是多队列网卡、NVMe SSD 的标配，可实现"一个队列对应一个中断、绑定一个 CPU 核心"的极致并行。
    - **LPI（局域外设中断）**：ARM GICv3/v4 引入的中断类型，配合 ITS（中断翻译服务）单元，将 PCIe 的 MSI/MSI-X 请求转换为内部 LPI，支持超大规模中断向量。

### 3. 处理器间中断（IPI / SGI）

- **核心特征**：多核系统中==🟡**CPU 核心之间主动发送的**==中断，是核间协同的核心机制。
- **架构对应**：x86 平台通过本地 APIC（LAPIC）发送 IPI；ARM 平台通过 SGI（软件生成中断）实现同等功能。
- **典型场景**：TLB 刷新（x86 的 TLB Shootdown）、调度抢占、函数广播、缓存一致性同步、系统停机时的多核停机、时钟事件广播等。
- **分类归属注意**：SGI 虽然由软件写寄存器**发起**，但它经 GIC 以硬件中断的形式**异步投递**到目标核心，因此归类属于异步硬件中断（GIC 的中断类型之一），不属于指令级的"软中断"（后者指 INT n / SVC 这类 CPU 指令）。

### 4. 不可屏蔽中断（NMI）

- **核心特征**：==🔴**最高优先级的硬件中断**==，无法通过普通中断屏蔽指令（如 x86 的 `cli`）关闭，保证极端场景下 CPU 必须响应。
- **两类典型场景**：
    - **硬件故障类**：如硬件看门狗超时、内存不可纠正 ECC 错误、总线致命错误，通常直接触发系统崩溃。
    - **调试监控类**：如 Linux 的 NMI Watchdog（死锁检测）、perf 硬件性能采样，利用 NMI 不可屏蔽的特性，在关中断场景下也能采集 CPU 状态，定位死锁与性能问题。

### 5. 本地中断（x86 Local APIC LVT）

- **核心特征**：由 CPU 核心**内部的本地资源**（而非外部引脚或总线消息）产生的每核私有硬件中断，x86 上经本地 APIC 的 LVT（本地向量表）直接投递到本核、不经过 IOAPIC；概念上与 ARM 的 PPI 对应（ARM 的本地定时器、PMU 等在 GIC 体系中归属 PPI，见 §1）。
- **典型来源（x86 LVT）**：
    - **本地定时器中断**：系统心跳（tick）与高精度定时的硬件基础，支持 TSC-deadline 模式；
    - **性能计数器溢出中断**：perf 硬件采样的中断来源；
    - **温度传感器中断**：CPU 过热保护与降频触发；
    - **APIC 错误中断、CMCI（可纠正机器检查中断）**：中断控制器自身错误与硬件可纠正错误的上报。
- **功能视角**：定时器中断、性能监控、温控等"本地/错误监控"功能类都落在这一机制类别上（见总览·维度四）。

## 二、同步中断（异常 Exception，广义"软件中断"）

同步中断不依赖外部物理电平或总线消息，完全由 **CPU 内部**产生：或是软件**主动**执行特定的中断指令申请陷入内核态（狭义软中断，见"陷阱"），或是程序运行中**被动**遇到无法继续的同步错误。触发时机与当前指令严格同步，中断向量号由 CPU 内部架构预定义，无需外部中断控制器参与。按可恢复性与返回行为分为三类：

### 1. 故障（Fault）—— 被动触发，可恢复

- **核心特征**：可恢复类异常，异常发生时 CPU 保存的指令指针（PC/RIP）**指向触发异常的当前指令**；异常处理完成后，返回并重新执行该指令。
- **常见类型**：
    - **缺页异常（Page Fault）**：最典型的故障类异常，既包含正常的按需调页、写时复制（COW）等可恢复场景，也包含非法地址访问、权限越界等不可恢复场景（此时内核会向进程发送 SIGSEGV 信号终止进程）。
    - **一般保护性异常（#GP）**：触发场景涵盖用户态执行特权指令、访问越权内存地址、段权限违规、部分架构下的非对齐内存访问等。
    - **除零异常（#DE）、非法操作码异常（#UD）**：均属于典型故障，处理后可重新执行（通常由内核模拟指令或上报信号）。

### 2. 陷阱（Trap）—— 主动触发，狭义"软中断"属于此类

- **核心特征**：预期内的主动触发，异常发生在**陷阱指令执行完成之后**，CPU 保存的指令指针指向当前指令的下一条；处理完成后直接继续执行后续代码，无需重跑原指令。
- **软中断指令（指令触发型，即狭义"软中断"）**——软件通过特定的汇编指令主动向 CPU 申请陷入内核态：
    - **INT n（Interrupt Instruction）**：x86 架构的软中断指令。`int 0x80`（32 位 x86）通过陷阱门触发，是标准陷阱实现，也是 Linux 早期著名的系统调用入口。
    - **SVC / SWI（Supervisor Call / Software Interrupt）**：ARM 架构下应用层调用内核服务的指令（用于实现系统调用；SWI 为旧名，ARMv7 起更名为 SVC）。
    - x86_64 的 `syscall`、ARM 的 `svc` 指令为快速系统调用机制，不走传统中断描述符表，但行为上仍属于同步陷阱。
- **其他典型陷阱**：断点异常（`int3`）、单步调试、溢出检测指令（`into`）均是程序主动插入的调试/检测点，属于典型陷阱。

### 3. 终止（Abort）—— 被动触发，不可恢复

- **核心特征**：严重的不可恢复错误，CPU 无法准确定位出错指令，保存的 PC 值无意义；内核通常无法修复，只能终止进程或触发内核崩溃（Kernel Panic/蓝屏）。
- **常见类型**：
    - **双重故障（#DF）**：典型场景为内核栈溢出，处理第一个异常时又触发新的异常；若双重故障处理过程中再触发异常，会进入三重故障，直接导致 CPU 硬件复位。
    - **机器检查异常（#MC）**：由硬件上报的物理故障（如缓存 ECC 错误、总线奇偶错误、内存不可纠正错误）；现代服务器 CPU 配合 ECC 内存可实现部分可纠正的 MCE 处理，并非全部直接崩溃。

## 三、Linux 内核的"软中断"（Softirq）—— 操作系统层面的下半部机制

**注意**：在 Linux 内核中，"软中断"这个概念被赋予了另一重含义。除了上述指令级的软中断指令外，Linux 内部实现了一种**下半部（Bottom Half）延迟执行机制**，也叫 **Softirq**——它不是 CPU 意义上的中断，而是内核的延迟处理执行上下文。

由于硬中断（如网卡收包）的处理函数需要立即执行且会关闭其他中断，为了防止系统卡死，Linux 将中断处理分为两部分：

- **上半部（Top Half，硬中断）**：只做最紧急的事情（如把网卡数据复制到内存），然后立刻释放 CPU。
- **下半部（Bottom Half，Linux 软中断/Softirq）**：延后执行耗时的任务（如 TCP/IP 协议栈的解析），在开中断环境下执行。

**Linux 内核中预定义的 10 种顶级 Softirq**：

- `HI_SOFTIRQ`：高优先级软中断
- `TIMER_SOFTIRQ`：内核定时器软中断
- `NET_TX_SOFTIRQ` / `NET_RX_SOFTIRQ`：网络发送/接收软中断（最常用）
- `BLOCK_SOFTIRQ`：块设备（硬盘 I/O）软中断
- `IRQ_POLL_SOFTIRQ`：IO 轮询软中断
- `TASKLET_SOFTIRQ`：基于软中断实现的 Tasklet 机制
- `SCHED_SOFTIRQ`：内核多核调度负载均衡软中断
- `HRTIMER_SOFTIRQ`：高精度定时器软中断
- `RCU_SOFTIRQ`：RCU 无锁机制垃圾回收软中断

## 四、总结与对比

### 4.1 中断术语汇总表

| 中断术语                     | 所属大类        | 触发驱动来源                             | 管理/规范体系             | 是否可被软件屏蔽   |
| ------------------------ | ----------- | ---------------------------------- | ------------------- | ---------- |
| **SPI**                  | 异步硬中断       | 外部物理硬件外设（如串口、老的网卡）                 | ARM GIC 体系          | 是          |
| **PPI**                  | 异步硬中断       | CPU 核心私有硬件（如 Local Timer）          | ARM GIC 体系          | 是          |
| **LPI**                  | 异步硬中断       | PCIe 等设备基于内存写入的硬件消息                | ARM GICv3/v4（ITS）   | 是          |
| **MSI / MSI-X**          | 异步硬中断       | PCIe 总线报文消息（网卡、nvme磁盘）             | PCI/PCIe 局部总线标准     | 是          |
| **IPI（x86）/ SGI（ARM）**   | 异步硬中断       | 另一个 CPU 核心发出                       | x86 APIC / ARM GIC  | 是          |
| **本地中断（x86 LVT）**        | 异步硬中断       | CPU 核心内部本地资源（定时器、性能计数器、温控、APIC 错误） | x86 Local APIC（LVT） | 是          |
| **NMI**                  | 异步硬中断       | 硬件灾难性故障信号/高级硬件采样                   | x86 / 各种 CPU 架构     | **否**      |
| **INT n / SVC（软中断指令）**   | 同步中断（陷阱）    | 软件代码明确编写的系统调用指令                    | CPU 指令集架构           | 否（直接陷入）    |
| **Fault / Trap / Abort** | 同步中断（异常）    | 指令执行错误或主动调试/检测点                    | CPU 指令集架构           | 否（同步，不可屏蔽） |
| **Softirq**              | 内核机制（非硬件中断） | Linux 内核为缓解硬中断压力的软件延时机制            | Linux 操作系统          | ——         |

### 4.2 同步异常 vs 异步中断核心对比

| 对比维度 | 同步异常（Exception） | 异步硬件中断（Interrupt） |
|---|---|---|
| 触发时机 | 与指令执行严格同步，执行当前指令时产生 | 与当前指令无关，随机异步触发 |
| 触发源 | CPU 内部，指令执行异常或主动触发 | 外部硬件、其他 CPU 核心 |
| PC 指向 | 故障：指向当前指令；陷阱：指向下一条 | 指向被打断处的下一条指令 |
| 可预期性 | 大部分可预期（如系统调用、缺页） | 完全随机，不可预期 |
| 中断向量 | CPU 架构预定义，固定编号 | 由中断控制器/操作系统动态分配与配置 |
| 典型代表 | 缺页、系统调用、断点 | 网卡中断、定时器中断、IPI |

## 五、易混淆概念澄清

1. **"软中断"一词的多重含义（本文最大的混淆点）**
    - **指令级狭义软中断**：`INT n`、`SVC/SWI` 等 CPU 指令——同步陷阱，用于系统调用；
    - **Linux 内核 Softirq**：下半部延迟处理机制——不是硬件中断，不占用硬件中断上下文，用于将中断处理中耗时的部分后移；
    - **广义软件中断**：有时泛指 CPU 内部产生的所有同步中断（异常）。
    语境不明时需先确认说的是哪一种。
2. **中断上半部 vs 下半部**：上半部即硬件中断处理函数，快速响应硬件、清中断标志、登记工作；下半部（软中断、Tasklet、工作队列）负责后续耗时的数据处理，在开中断环境下执行。
3. **ARM SGI 与 IPI 的关系**：SGI 是 ARM GIC 提供的软件生成中断（一种中断类型），IPI 是核间中断的功能概念；ARM 平台的 IPI 功能就是通过 SGI 中断实现的，二者是实现与功能的对应关系。注意 SGI 虽由软件发起，但经 GIC 异步投递，分类上属于硬件中断，而非指令级软中断。
4. **功能叫法与机制类别不在同一层级**："I/O 中断""定时器中断""网卡 IRQ"是**功能/来源层面的叫法**（见总览·维度四），不与 SPI、MSI-X、PPI 等机制类别并列——现代网卡 IRQ 的机制实现就是 MSI-X，ARM 定时器中断的机制实现是 PPI，x86 本地定时器的机制实现是 LAPIC LVT 本地中断。跨层混比会产生"网卡中断和 MSI-X 谁包含谁"这类无意义问题。
5. **ARM 上网卡/磁盘的 MSI/MSI-X 与 LPI 的关系**：在 GICv3+ 平台上，设备发出的 MSI/MSI-X 写请求由 GIC 的 ITS（中断翻译服务）翻译成 LPI，再经 Redistributor 投递到目标 CPU 核——**MSI/MSI-X 是设备侧的"发出形式"（PCIe 总线协议层），LPI 是 GIC 侧的"接收类型"（中断控制器层）**，不是两种并列的中断（4.1 表中分列两行即为此故）；x86 上同样的 MSI/MSI-X 写直接落入 Local APIC，没有 LPI 这个中间类型。
