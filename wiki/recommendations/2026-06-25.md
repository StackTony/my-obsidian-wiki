## 三、延伸学习方向

基于已有知识 + 新发现内容，推荐 **2 个新的延伸学习技术点**：

| 延伸方向 | 与当前主题关联 | 学习价值 |
|----------|----------------|----------|
| **1. Loopcraft：循环堆叠与嵌套设计** | 已有 Harness Engineering（单次运行可靠）；Loop Engineering（多次运行自主）；Swyx 提出"堆叠循环"——内层干活，外层改进 | 理解 Agent 不是单个循环而是**嵌套循环系统**：内层 Agent Loop→中层 Verification Loop→外层 Event-Driven Loop→顶层 Hill Climbing Loop。与已有 Linux 内核子系统交互（softirq 嵌套分发、preempt_count 层级追踪）形成跨领域类比 |

## 四、深入推荐

### 4.1 🔥 Addy Osmani：Loop Engineering（命名之作）

| 标题 | 链接 | 类别 | 摘要 | 重点内容 |
|------|------|------|------|----------|
| **Loop Engineering** | [addyosmani.com](https://addyosmani.com/blog/loop-engineering) / [O'Reilly](https://www.oreilly.com/radar/loop-engineering) | 原理介绍 | **正式命名之作**：Loop engineering is replacing yourself as the person who prompts the agent. You design the system that does it instead. | 五要素+记忆脊柱：Automations（心跳/发现/分流）、Worktrees（并行隔离）、Skills（项目知识编码）、Connectors/MCP（连接真实工具）、Sub-agents（Maker/Checker 分离）、External State（磁盘而非上下文）。Codex vs Claude Code 五要素对照表。`/goal` 和 `/loop` 两个核心原语。三大风险：验证仍在你手上、理解腐烂加速、舒适姿态即危险姿态（认知投降） |

**核心贡献**：
- 五要素已成为 Loop Engineering 的标准解剖学
- Codex 和 Claude Code 的原语对照证明"Loop 是跨工具可移植的设计"
- ` /goal ` = run-until-done（单独小模型验证是否达成目标），` /loop ` = 定时重跑
- "Loop 比 Harness 高一层"：Harness 让一次运行可靠，Loop 让多次运行自主、定时发现、自己喂自己

### 4.2 🔥 LangChain：四层 Loop 框架（工程分层）

| 标题 | 链接 | 类别 | 摘要 | 重点内容 |
|------|------|------|------|----------|
| **The Art of Loop Engineering** | [LangChain/Sydney Runkle](https://www.langchain.com/blog/the-art-of-loop-engineering) | 技术分析 | **四层 Loop 框架**：Agent Loop→Verification Loop→Event-Driven Loop→Hill Climbing Loop，价值在第三四层复合 | Loop 1: create_agent（模型+工具循环直到完成）。Loop 2: RubricMiddleware（输出评分→不符则反馈回重试）。Loop 3: LangSmith Deployment（cron/webhook触发→Agent在系统中持续运行）。Loop 4: LangSmith Engine（分析trace→自动改进Harness配置）。人类监督可在每层注入。Satya Nadella：早建学习循环的组织将获得难以复制的复合优势 |

**层级演进**：
```
Loop 1: Agent Loop        → 自动化工作（模型调用工具直到完成）
Loop 2: Verification Loop → 确保质量（评分→反馈→重试）
Loop 3: Event-Driven Loop → 大规模自动运行（cron/webhook/Slack触发）
Loop 4: Hill Climbing Loop → 自动改进（分析trace→优化Harness）
     ↑ 价值从1→4递增，1-2是基础，3-4是复合
```

| Loop 嵌套 ↔ Linux 内核子系统嵌套 | softirq 嵌套分发、preempt_count 层级追踪 = Loopcraft 的"堆叠循环"——每层有自己的终止条件和状态管理 |
| Loop 验证器 ↔ DFX 工具类型 | Computational Sensor（Linter/类型检查=ftrace确定性追踪）vs Inferential Sensor（LLM-as-judge=perf采样概率分析）——同构 |

## 九、核心术语表

### Loop Engineering 核心术语

| 术语 | 定义 |
|------|------|
| **Loop Engineering** | 循环工程，设计 Agent 不仅一次响应而是行动→观察→决策→重复直到目标达成的循环系统——你不是逐轮指挥者，你是系统设计者 |
| **五要素（Osmani Anatomy）** | Automations（定时发现/分流）、Worktrees（并行隔离）、Skills（项目知识编码）、Connectors/MCP（连接真实工具）、Sub-agents（Maker/Checker分离）+ External State（记忆脊柱） |
| **四代范式演进** | Prompt Engineering（2022-24）→ Context Engineering（2025）→ Harness Engineering（2026初）→ Loop Engineering（2026.6）。层叠而非替代关系 |
| **Loop vs Harness** | Harness 让一次运行可靠（环境+约束+反馈）；Loop 让多次运行自主（定时+发现+自己喂自己+Maker/Checker）。Loop 比 Harness 高一层 |
| **`/goal` 原语** | Run-until-done：设定可验证完成条件，每轮由独立小模型评估是否达标，达标才停止。Codex 和 Claude Code 同名同功能 |
| **`/loop` 原语** | 定时重跑：按间隔重复运行同一Prompt。Claude Code 内置 |
| **Maker/Checker 分离** | 做代码的 Agent 和检查代码的 Agent 必须是不同的——模型给自己的作业打分太宽容 |
| **Loopcraft** | 堆叠循环的艺术（Swyx）：Agent 不是单个循环而是嵌套循环系统——内层干活、中层验证、外层运行、顶层改进 |
| **Salty Lesson** | 盐味教训（Swyx）：对应 Sutton 的 Bitter Lesson——模型会持续变强，你写的手工规则会被超越，投资在可随模型规模化的Loop设计上 |
| **验证器瓶颈** | 在任何Loop中，验证器是瓶颈不是模型——弱验证器的Loop=昂贵的垃圾 |
| **Hill Climbing Loop** | 爬坡循环（LangChain Loop 4）：分析生产trace→自动改进Harness配置。价值复合层 |
| **Event-Driven Loop** | 事件驱动循环（LangChain Loop 3）：cron/webhook/Slack触发→Agent在系统中持续运行 |
| **Verification Loop** | 验证循环（LangChain Loop 2）：输出评分→不符则反馈→重试 |
| **on-the-loop vs in-the-loop** | 在循环之上 vs 在循环之中：人类从逐轮审批（in）退出到设计规则（on）——Loop自主执行，人类只在不可逆操作时介入 |
| **认知投降（Cognitive Surrender）** | 舒适地接受Loop产出的一切——Loop越自主越容易放弃思考，最危险的姿态 |
| **理解腐烂（Comprehension Debt）** | Loop越快交付你没亲手写/看的代码，仓库里有的和你脑子里真正搞懂的差距就越大 |
| **Loop 四条件测试** | Boris/01Coder的判断标准：①任务每周重复 ②验证能自动化 ③Token预算扛得住 ④Agent有资深工程师那套工具 |

### 企业级 Loop 术语

| 术语 | 定义 |
|------|------|
| **Laptop Loop** | 笔记本循环，Loop运行在工程师个人机器上——随笔记本关闭、凭证明文存储、无成本上限、多副本无注册 |
| **Governed Runtime** | 治理运行时，Loop运行在平台级基础设施上——身份/预算/审批/追踪/不随终端关闭 |
| **Noor 故事** | 典型案例：笔记本循环三周完美→财务问Token暴涨、安全问凭证在哪、总监问有多少Loop谁批准了——笔记本是错误的运行时 |
| **Agent Definition YAML** | 声明式Agent定义：模型/技能/连接器/子代理/触发器/审批门/预算上限——类似K8s Deployment |
