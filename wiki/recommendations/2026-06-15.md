## 四、深入推荐

### 4.7 🔥 新增：arXiv 学术定义 — Harness 必要充分条件

| 标题 | 链接 | 类别 | 摘要 | 重点内容 |
|------|------|------|------|----------|
| **What makes a harness a harness: necessary and sufficient conditions** | [arXiv 2606.10106](https://arxiv.org/abs/2606.10106) | 原理介绍 | **首个学术级定义**：提出 Harness 的四个必要条件（Agent Loop / Tool Interface / Context Management / Control Mechanisms），并操作化为包含/排除测试 | 基因alogy追溯（马挽具→测试harness→ML评估harness→Agent harness）、六系统验证（Claude Code/Codex/Aider/Cline/OpenHands/SWE-agent）、与Agent Framework/SDK/IDE Plugin/Eval Harness/Orchestrator的边界划分 |

**核心贡献**：首次给出 Harness 的必要充分条件形式化定义，解决了"什么是 Harness"的语义混乱问题。每个条件去一个就不再能称为 Harness：
- 无 Agent Loop → 一次性生成器，不是 Agent
- 无 Tool Interface → 模型困在自己的窗口里，无法行动
- 无 Context Management → 多步任务信息稀释在历史累积中
- 无 Control Mechanisms → 无信任、无审计、无限制

### 4.8 🔥 新增：Meta-Harness — Harness 之上的新抽象层

| 标题 | 链接 | 类别 | 摘要 | 重点内容 |
|------|------|------|------|----------|
| **Databricks Omnigent: A Meta-Harness to Combine, Control and Share Your Agents** | [Databricks Blog](https://www.databricks.com/blog/introducing-omnigent-meta-harness-combine-control-and-share-your-agents) | 架构图 | **新概念 Meta-Harness**：Harness 让模型可互换，Meta-Harness 让 Harness 可组合 | Runner+Server 两层架构、Composition（多Harness/多模型组合）、Control（策略驱动而非Prompt驱动）、Collaboration（实时共享URL协作）、YAML自定义Agent声明式定义、Apache 2.0 开源 |

**层级演进**：
```
Model → Harness → Meta-Harness
  ↑        ↑           ↑
推理力    运行控制层    组合/协作/策略层
```

## 九、核心术语表（更新版）

### 🆕 新增术语

| 术语 | 定义 |
|------|------|
| **Meta-Harness** | 元 Harness，Harness 之上的组合/控制/协作层。单个 Harness 是信息孤岛，Meta-Harness 让不同 Harness 互操作（Databricks Omnigent: Composition/Control/Collaboration） |
| **Loop Engineering** | 循环工程，设计 Agent 行动→观察→决策→重复的循环架构——不是一次响应而是持续迭代直到目标达成（三种模式：Retry/PEV/Exploration） |
| **Context Development Lifecycle (CDLC)** | 上下文开发生命周期，Context 不是写一次的文件而是有 Generate→Evaluate→Distribute→Observe 四阶段的工程产物（Tessl/Patrick Debois） |
| **Context Flywheel** | 上下文飞轮，更好Context→更好Agent输出→更好信号→更好Context 的四方向复合回报循环（Agent质量+团队学习+组织一致+技能传承） |
| **Task Evals** | 任务评估，对比有无 Skill 的 Agent 输出差异来衡量 Skill 是否真正在引导行为——Skill 的"单元测试"（Tessl） |
| **Necessary and Sufficient Conditions for Harness** | Harness 必要充分条件：Agent Loop + Tool Interface + Context Management + Control Mechanisms（arXiv 2606.10106） |
| **AI Factory** | AI 工厂，以 GitHub 为真相源、Linear 为规划、Slack 为触发协调的 Agent 生产流水线模式（Escape/Carossio SF调研） |
| **Builder** | 建造者，新角色：端到端拥有问题、用 Agent 覆盖自己缺失技能的人——设计师/PM/创始人都能成为 Builder |
