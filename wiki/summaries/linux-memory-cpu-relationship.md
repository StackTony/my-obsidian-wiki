# 虚拟内存与分页原理（内存与CPU之间的关系）

本文是操作系统内存管理的教材式梳理（Tanenbaum《现代操作系统》第3章脉络），从物理内存的最朴素使用方式一路推到分页、TLB 与页面置换算法，是理解 [[concepts/linux-memory-management]] 中 meminfo/Page Cache 等具体机制的底层理论基础。

## 核心观点

- 内存管理的演进主线是**不断加深抽象**：无抽象（直接访问物理内存）→ 交换技术 → 地址空间 → 虚拟内存/分页。
- **地址空间**是操作系统给进程的核心抽象——每个进程看到一段从 0 开始的连续虚拟地址，与实际物理内存解耦。
- **分页**把虚拟地址空间切成固定大小的"页"、物理内存切成同样大小的"页框"，由 MMU 完成映射，是现代虚拟内存的实现基础。
- 页表本身会成为新的空间开销（32 位下每个进程 4MB 页表），因此有了**多级页表**与**倒排页表**两条解法。 ^[inferred]
- 页面置换算法没有"最好的通用解"：**老化算法（aging）与工作集时钟算法（WSClock）是工程上的最优选择**——二者都以近似 LRU 且可实现为代价，换取可接受的缺页率。

## 关键细节

### 从无抽象到地址空间

| 阶段 | 做法 | 问题 |
|------|------|------|
| 无存储器抽象 | 程序直接使用物理地址 | 多个程序无法同时驻留内存 |
| 基址 + 界限寄存器 | 运行时把虚拟地址加上基址，界限寄存器防越界 | 每次访存都要相加与比较；进程整体必须连续存放 |
| 基址/变址寄存器 | 编译时把程序拆成代码段（只读、可共享）和数据段（可写），各自加基址 | 段的划分依赖编译期信息，灵活性受限 |

**交换技术（swapping）**：内存不足时把整个进程换出到磁盘，需要时再换入。空闲内存用**位图**或**空闲链表**管理，长期运行后需要**内存紧缩（compaction）**——代价很高，且只对固定分区结构适用。

### 空闲内存管理

- **位图**：每个分配单元 1 bit（0 空闲 / 1 占用）。查找连续 k 个 0 需按字扫描，速度慢。
- **空闲链表**：按地址排序的段链表，每项记录空闲块起始地址、长度和指向下一项的指针。

四种适配算法：

| 算法 | 行为 | 特点 |
|------|------|------|
| 首次适配 first fit | 从头找第一个够大的块 | 速度最快，常用 |
| 下次适配 next fit | 从上次位置继续找 | 与首次适配相当 |
| 最佳适配 best fit | 找最接近需求的块 | 产生大量无用小碎片 |
| 最差适配 worst fit | 找最大的块 | 大空闲块被迅速打散，浪费严重 |

另有**快速适配（quick fit）**：为常见大小各维护一条空闲链表，进一步加速。

### 分页与页表项

虚拟地址空间被划分为固定大小的**页（page）**，物理内存划分为同样大小的**页框（page frame）**，MMU 通过页表完成 VA→PA 转换。页表项通常包含：

- **页框号**——映射目标
- **在/不在位**（有效位）——该页当前是否在内存中
- **保护位**——读/写/执行权限
- **修改位**（脏位）——换出时是否需要写回磁盘
- **访问位**（引用位）——置换算法的输入信号
- **禁用缓存位**——强制该页绕过缓存

**缺页中断流程**：MMU 发现"在/不在位"为 0 → CPU 陷入内核 → 缺页中断处理程序挑选一个页面换出（脏页需先写回）→ 调入缺失页并更新页表 → 重新执行触发缺页的那条指令。

### TLB：为分页加速

分页让每次访存变成"先读页表再读数据"的两次访问，性能减半。**TLB（转换检测缓冲区）**位于 MMU 内部，容量通常为 8~64 项，缓存最近使用过的页表项：

- 命中 → 直接得到物理地址，无需访问内存中的页表
- 不命中 → 访问页表（多级页表需多次内存访问），再填入 TLB

TLB 很小，因此**缺页与 TLB 失效是两种不同的失效**：页在内存但 TLB 未命中为**软失效（soft miss）**，页不在内存需要读磁盘为**硬失效（hard miss）**，后者对应 minor / major page fault 的区别。TLB 的换入换出策略由硬件或操作系统决定。详见 [[summaries/linux-tlb-management]]。

### 大地址空间的解法

| 方案 | 思路 | 代价 |
|------|------|------|
| 多级页表 | 把页表本身再分页，只保留用到的部分 | 一次访存需要多次页表访问（由 TLB 缓解） |
| 倒排页表 | 每个物理页框一项，记录 (进程, 虚拟页号) | 空间开销与物理内存成正比而非虚拟空间；查找需哈希，且页号在表中按物理页排序 |

### 页面置换算法

| 算法 | 策略 | 评价 |
|------|------|------|
| OPT（最优） | 换出未来最久不再访问的页 | 不可实现，仅作为理论基准 |
| NRU（最近未使用） | 按访问位 R / 修改位 M 分四类，优先换出 R=0,M=0 | 实现简单，性能一般 |
| FIFO | 先进先出 | 可能换出频繁使用的页，存在 Belady 异常 |
| 第二次机会 | FIFO + 检查 R 位，R=1 则清 0 后放到队尾 | FIFO 的低成本改进 |
| 时钟 | 用环形链表实现第二次机会，指针循环扫描 | 工程实现形式 |
| LRU | 换出最长时间未被访问的页 | 效果好，但完全实现代价极高（每次访问都要更新），硬件几乎不可行 |
| NFU（不经常使用） | 每页设计数器，时钟中断时把 R 位累加到计数器 | 只记录频次，不区分访问时间远近 |
| **老化（aging）** | 计数器右移后再把 R 位加到最高位——等同于按时间衰减的频次 | **推荐**，以较低成本模拟 LRU |
| 工作集（working set） | 记录每页最近 k 次访问时间，换出不在工作集窗口内的页 | 效果好，需时间戳开销 |
| **WSClock** | 工作集算法 + 时钟实现：扫描中 R=0 且 age>τ 即换出，写过的页先写回 | **推荐**，兼顾效果与开销 |

**结论**：老化算法与 WSClock 是实践中最优的两种置换算法。 ^[inferred]
